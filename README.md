# 要素与介绍核对

先从合同提取要素表，再拿要素表和公司介绍、经理介绍底稿去对一页通。对不上的地方写成 Word 修订，下载后在「所有标记」里能看到红字。

日常使用这个网站：https://zylugarry-lab.github.io/intro-baseline-review/

合同和一页通只在浏览器里处理，不会上传。公司介绍和经理简介改完要点「保存并同步」，其他人打开这个网页会看到这一版。

## 四步

1. **合同要素**
   - 上传一份或多份集合计划合同，doc 或 docx 都可以。每份合同单独生成要素表，下载的 Excel 里各占一个工作表。只下载要素、不去对一页通也可以。
   - 产品风险等级按通用版或建行版生成。销售机构如果另给了评级，在下拉里选上，这句话会补进风险表述。

2. **内容底稿**
   - `assets/manager-introductions.xlsx`：姓名、简介、从业日期、投资起始日期。
   - `assets/company-introduction-general.docx`：通用版公司介绍。
   - `assets/company-introduction-ccb.docx`：建行版公司介绍。
   - 从业年限、投资年限用制作日期减去对应起始日期，按 365 天下取整。不满一年保留一位小数。
   - 公司介绍和经理简介在页面上直接改。每张卡片有「保存并同步」，保存后的版本会在其他人打开网页时读到。

3. **对照一页通**
   - 上传一页通，doc 或 docx 都可以。公司介绍或经理介绍和底稿不一致时，直接改成底稿的文字。投资经理以要素表名单为准，多的删除，少的用底稿简介补上。开头的产品名称、单独一行的产品代码，以及产品要素表，都按网页上当前这份要素修改。网页上改过或补过的格子，一页通和海报都用改过的文字。底部风险揭示跟着要素里的风险等级改。一页通如果写了锁定期天数，会改成和开放期里的天数一致。下载为 docx，修改以修订痕迹保留，文件名是「【一页通  年月】合同产品简称」，去掉「集合资产管理计划」，年月跟制作日期。新上传的合同会成为当前合同，已上传的一页通会按它重写。删掉一份合同后，按它改过的一页通结果会清掉；合同全部删掉时，一页通也清掉。
   - 合同没有业绩报酬时，要素写成「本集合计划不收取业绩报酬。」有业绩报酬时，合同写明超过计提基准提取一档比例的，按这一档写；其余补上三段计提标准。两种都在最后写上「业绩报酬计提标准以公告为准。业绩报酬计提日为计划分红登记日、投资者退出日和计划终止日。业绩报酬计提基准不构成收益承诺，实际收益可能低于该业绩报酬计提基准。」R1、R2、F1、F2 的具体数字在表格里手填。
   - 一页通里的风险等级和最下面的风险揭示，改成和要素表里的产品风险等级一致，包括销售机构另给的评级。
   - 没被改到的段落保持原样。

4. **生成海报**
   - 第四步可以选择通用海报或建行海报。通用海报在产品名称下面写「风险等级：R3（中风险）」。建行海报用持营版式：名称下直接写风险代号，产品代码和「起正式开放」单独成框，正文写起购金额、业绩报酬、开放规则和这一期开放期。
   - 通用海报上的适合投资者写成简写，R3 对应 C3-C5。公司介绍选建行版、海报仍用通用版式时，适合投资者写成 C3（平衡型）、C4（进取型）、C5（激进型）。
   - 开放日期或销售日期在第四步填写。建行海报另外填这一期开放期。产品代码用第一步里填的代码，老产品会写到海报上。
   - 通用海报文件名是「【海报  年月】合同产品简称」。建行海报文件名是「【持营海报年月】合同产品简称」。

## 网站

打开 https://zylugarry-lab.github.io/intro-baseline-review/ 。公司介绍和经理简介在「第二步 · 内容底稿」里直接改，点「保存并同步」之后，其他人打开网页会看到这一版。改乱了可以点「恢复内置」，再保存一次，同步的版本也会回到内置底稿。

内置底稿仍是 `assets` 里的 Excel 和两份 Word。同步的是网页上保存的那一版；某台浏览器如果有还没点保存的修改，会先留着这台浏览器里的内容。

本机预览时，在这个目录执行 `python3 -m http.server 4173`，再打开 `http://127.0.0.1:4173/`。不要直接双击 `index.html`。
